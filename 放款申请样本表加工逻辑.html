逐步骤

  1. 1

    定观察日

    param_obs_date

    目的：给全流程一个统一截止时点，后面所有“是否成熟”都和 obs_dt 比。

    输入edw_ewa.dwb_asset_debt_dtl_snp→输出param_obs_date

    取借据快照表里的最大日期：

    SELECT MAX(TO_DATE(dt)) AS obs_dt
FROM edw_ewa.dwb_asset_debt_dtl_snp
    本例：obs_dt = 2026-10-22，整张表所有申请共用这个时点。
  2. 2

    把多期借据压成日快照

    stg_debt_snp

    目的：把原始借据明细压成 listing × 快照日一行，后面取到期日、首还日、状态、余额都只查这张表。

    输入dwb_asset_debt_dtl_snp→输出stg_debt_snp
    • 扫描窗口：最早申请时间前 1 个月至 obs_dt，避免全表扫。
    • 按 listing_id, stat_date 分组，金额求和。
    • first_repay_time 只取 period_no = 1 的实还时间。
    • 多期状态按 逾期中 > 未结清 > 已结清 取最严重。
    GROUP BY listing_id, stat_date

MAX(CASE WHEN period_no = 1
         THEN user_actual_repay_time END) AS first_repay_time
MAX(CASE debt_status WHEN 4 THEN 3 WHEN 1 THEN 2 WHEN 2 THEN 1 END)
  AS status_priority

  3. 3

    取申请池并排序

    apply / ranked

    目的：取所有有效申请，给同一用户的申请编号，并给已放款申请一个放款顺序。

    输入ods_ewa.aus_ewa_loan_biz_t_loan_application→输出apply ranked
    • apply：过滤 isactive = 1，按用户申请时间生成 apply_seq。
    • ranked：只看 DISBURSE_SUCCESS，按放款时间生成 application_rank。
    ROW_NUMBER() OVER (PARTITION BY user_id
  ORDER BY inserttime, loan_no) AS apply_seq

ROW_NUMBER() OVER (PARTITION BY user_id
  ORDER BY apply_disburse_time NULLS LAST, loan_no) AS application_rank
    本例：LN00003185，user_id 1007907，listing_id 2301，status DISBURSE_SUCCESS；申请时间 2026-09-13 20:10:37，放款时间 20:17:15。该用户只有这一条申请，apply_seq = 1、application_rank = 1。
  4. 4

    取发标策略事件

    event

    目的：把申请和发标策略调用对上，拿 application_id、appId、策略时间、重试次数。

    输入ods_ewa.aus_ewa_risk_risk_event_task→输出event
    • 过滤 biz_id = '20050' 且 flow_id LIKE 'LN%'。
    • 同一 flow_id 可能多次调用，取 updatetime 最新的一条。
    • appId 从 params JSON 里取。
    ROW_NUMBER() OVER (PARTITION BY flow_id
  ORDER BY updatetime DESC, inserttime DESC) AS rn
-- WHERE rn = 1
GET_JSON_OBJECT(params, '$.appId') AS app_id
    本例：flow_id LN00003185，biz_id 20050，application_id 11756，appId 1000008269，strategy_time 2026-09-13 20:10:37，retry_count 0。
  5. 5

    匹配申请前最近一次戳额

    credit / credit_matched

    目的：给每条申请找申请前最近一次戳额，得到 last_limit_time 和 last_limit_flow_id。

    输入aus_listing_tb_loan_limit_apply risk_event_task→输出credit credit_matched
    • credit 是两类事件的并集：额度申请 biz_type = 400（优先级 1）、风险事件 biz_id = 10000（优先级 2）。
    • 按 user_id 关联，只取 credit_time <= apply_time。
    • 同一申请多条候选时，按优先级、时间倒序、id 倒序取第一条。
    ROW_NUMBER() OVER (
  PARTITION BY loan_no
  ORDER BY source_priority, credit_time DESC, credit_id DESC
) AS rn
-- JOIN credit s ON a.user_id = s.user_id
--             AND s.credit_time <= a.apply_time
    本例：命中额度申请 id 10814，biz_type = 400，inserttime 2026-09-13 20:08:46（申请前 2 分钟）→ last_limit_time = 2026-09-13 20:08:46。10-16 的 401 在申请之后、9-24 的 404 类型不对，都不取。

    取 due+31 标签快照，判断 FPD 是否成熟

    base

    目的：在 due+31 再取一次借据，得到最终标签日；同时判断 FPD3/7/14/15/30 每一档是否已经可以下结论。

    输入latest stg_debt_snp→输出base
    • 按 stat_date = label_obs_dt 关联借据快照，得到 label_* 字段。
    • label_obs_day：优先取 due+31 快照里的首还日；缺失则取 obs_dt 前已记录的首还日；再缺取 due+31。
    • FPD-X 成熟：LEAST(首还日, due+X) < obs_dt，成熟记 obs_cnt = 1；未成熟 obs_cnt = 0，坏标签为 NULL。
    CASE WHEN is_deal = 1 AND debt_listing_id IS NOT NULL
      AND LEAST(COALESCE(TO_DATE(first_repay_time), obs_dt),
                DATE_ADD(init_due_date, 15)) < obs_dt
     THEN 1 ELSE 0 END AS y_fpd15_obs_cnt

    展开 MOB 观测点，算 5+ / 30+ 标签

    mob_obs / mob_label_*

    目的：在放款后每个已到的月末判断当前是否 5+/30+、历史是否 5+/30+。

    输入base stg_debt_snp→输出mob_obs mob_label_wide
    • EXPLODE(SEQUENCE(0, 4)) 展开 mob0~mob4，只保留月末 ≤ obs_dt 的观测点。
    • 按观测日关联快照：current_overdue_days >= 5 记 5+，> 30 记 30+；ever 用 hist_overdue_days。
    • 只把 mob1/2/3 透成 y_mob1/2/3_*；mob0 只用于后面的追踪。
    CROSS JOIN (SELECT EXPLODE(SEQUENCE(0, 4)) AS mob_no) m
WHERE LAST_DAY(ADD_MONTHS(TO_DATE(disburse_time), m.mob_no)) <= obs_dt

CASE WHEN current_overdue_days >= 5 THEN 1 ELSE 0 END AS is_5plus

  10. 10

    算 MOB 剩余本金与 DPD

    mob_track_*

    目的：在每个 MOB 观测点取最近一天快照，记录剩余本金和 DPD，供账龄追踪使用。

    输入mob_obs stg_debt_snp→输出mob_track_wide
    • 在放款日到观测日之间找快照；mob0 允许往后多取 7 天。
    • 优先取观测日或之前最近的一天；之前没有，才取之后最近的一天。
    • 透成 mob0~mob4 的剩余本金、当前 DPD、历史 DPD。
    ROW_NUMBER() OVER (
  PARTITION BY loan_no, mob_no
  ORDER BY CASE WHEN stat_date <= mob_obs_dt THEN 0 ELSE 1 END,
           CASE WHEN stat_date <= mob_obs_dt
                THEN DATEDIFF(mob_obs_dt, stat_date)
                ELSE DATEDIFF(stat_date, mob_obs_dt) END
) AS rn
    本例：mob0 取 2026-09-30 快照：estimate_principal_remaining_mob0 = 200，dpd_days_mob0 = 12，dpd_days_ever_mob0 = 12；mob1~4 为空。

    派生全部标签与维度

    labeled

    目的：把快照值翻译成所有 y_*，并补 user_type、放款月/季度、在贷天数，最后拼上 MOB 与模型分。

    输入base mob_label_wide mob_track_wide model_log→输出labeled
    • 到期标签：y_due_dpd / y_due_ever_dpd 直接取 label 快照；逾期、5+、30+ 以及金额标签由它派生，无标签快照记 NULL。
    • FPD 坏标签：只有成熟（obs_cnt = 1）才计算；label_obs_day > due+X 记 1，否则 0，未成熟记 NULL。
    • 时点标签：y_obs_* 看 obs_dt 当天，仅对 is_deal = 1 计算。
    • 期限：合同天数 = due − 放款日；实际天数 = 首还日 − 放款日；首还早于到期日记提前结清。
    • 新老客：放款时间（未放款取申请时间）≤ 首笔放款时间为 New；无放款记录记 New。
    CASE WHEN y_fpd15_obs_cnt = 1
     THEN CASE WHEN label_obs_day > DATE_ADD(init_due_date, 15)
               THEN 1 ELSE 0 END
END AS y_fpd15_ovd_cnt

CASE WHEN first_disburse_time IS NULL THEN 'New'
     WHEN COALESCE(disburse_time, apply_time) <= first_disburse_time
          THEN 'New'
     ELSE 'Old' END AS user_type
