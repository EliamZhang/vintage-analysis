# 第一步：完善主表（SQL）

> 现行 `现行vintage计算代码.sql` 只作字段口径参考，不沿用它的表关联方式。

## 一、主表核对结论

基于 `model.tmp_eliam_wagego_application`（`ods_ewa.aus_ewa_risk_risk_event_task` 的场景补充版）核对：

- 181,477 行 = 181,477 个 `flow_id`（一行一次场景执行），45,638 个用户，时间范围 2026-06-25 ~ 2026-10-20
- 事件分三类：

| event_type | scenario_name | biz_id | 行数 | 关键特征 |
|---|---|---|---|---|
| 借款申请 | 放款策略 | 20050 | 33,478 | `flow_id` 即 `LN...` 放款号；`application_id` 有值且唯一；status 全为 20 |
| 授信跑额 | 戳额、进首页跑额、还款后跑额（非逾期）、失败重试跑额、进发表页跑额、离线跑额 | 10000 / 10004 / 10001 / 10006 / 10005 / 10003 | 109,636 | `flow_id = appId@user_id@biz_id@uuid`；无 `application_id` |
| CDS 拉数 | 未知场景 | 40000 | 38,363 | `flow_id = CDS-EWA-uuid`；`application_id` 有值但不是借款申请 |

- status 分布：`20` 成功 144,857；`-3` 失败 36,307；`10` 处理中 293；其余 20
- 放款策略全部 `status=20`：本表只记录执行成功的借款，策略拒绝的申请不在表内，后续全量借款申请需另接申请表。

## 二、第一步要完善的点

在原主表构建 SQL 上增加：

1. `event_type`：区分借款申请 / 授信跑额 / CDS 拉数
2. `status_desc`、`is_success`：把状态码翻译成可读口径
3. 时间字段转 `timestamp`
4. 从 `params` 解析 `app_id`、`institution`、`refresh_days`、`dpd`、`repay_amount`
5. 借款申请行单独产出 `loan_no`（即 `flow_id`）
6. 过滤 `is_active = 1`，去掉 CTAS 里无意义的 `ORDER BY`

## 三、主表构建 SQL

```sql
DROP TABLE IF EXISTS model.tmp_eliam_wagego_application;
CREATE TABLE model.tmp_eliam_wagego_application AS
SELECT
     a.id
    ,a.flow_id
    ,a.user_id
    ,CAST(a.biz_id AS STRING)                                        AS biz_id
    ,NULLIF(CAST(a.application_id AS STRING), '')                    AS application_id
    ,CASE CAST(a.biz_id AS STRING)
         WHEN '10000' THEN '戳额'
         WHEN '10001' THEN '还款后跑额（非逾期）'
         WHEN '10002' THEN '换卡跑额'
         WHEN '10003' THEN '离线跑额'
         WHEN '10004' THEN '进首页跑额'
         WHEN '10005' THEN '进发表页跑额'
         WHEN '10006' THEN '失败重试跑额'
         WHEN '20050' THEN '放款策略'
         ELSE '未知场景'
     END                                                             AS scenario_name
    ,CASE CAST(a.biz_id AS STRING)
         WHEN '20050' THEN 'loan_apply'
         WHEN '40000' THEN 'cds_pull'
         ELSE 'credit_run'
     END                                                             AS event_type
    ,CAST(a.status AS INT)                                           AS status
    ,CASE CAST(a.status AS INT)
         WHEN 20  THEN 'success'
         WHEN -3  THEN 'failed'
         WHEN 10  THEN 'processing'
         ELSE 'other'
     END                                                             AS status_desc
    ,CASE WHEN CAST(a.status AS INT) = 20 THEN 1 ELSE 0 END          AS is_success
    ,CAST(a.retry_count AS INT)                                      AS retry_count
    ,CAST(a.inserttime  AS TIMESTAMP)                                AS inserttime
    ,CAST(a.updatetime  AS TIMESTAMP)                                AS updatetime
    ,CAST(a.resume_status AS INT)                                    AS resume_status
    ,a.error_msg
    ,a.params
    ,a.source_msg
    ,GET_JSON_OBJECT(a.params, '$.appId')                            AS app_id
    ,GET_JSON_OBJECT(a.params, '$.institution')                      AS institution
    ,CAST(GET_JSON_OBJECT(a.params, '$.refreshDays') AS INT)         AS refresh_days
    ,CAST(GET_JSON_OBJECT(a.params, '$.dpd')        AS INT)          AS dpd
    ,CAST(GET_JSON_OBJECT(a.params, '$.repayAmount') AS DOUBLE)      AS repay_amount
    ,CASE WHEN CAST(a.biz_id AS STRING) = '20050'
          THEN a.flow_id END                                         AS loan_no
    ,a.dw_cre_date
    ,a.dw_upd_date
FROM ods_ewa.aus_ewa_risk_risk_event_task a
WHERE CAST(a.is_active AS INT) = 1
;
```

## 四、验收 SQL

```sql
-- 1. 总量与唯一性：应为 181,477，id / flow_id 均唯一
SELECT COUNT(*)                  AS row_cnt,
       COUNT(DISTINCT id)        AS id_cnt,
       COUNT(DISTINCT flow_id)   AS flow_cnt
FROM model.tmp_eliam_wagego_application;

-- 2. 事件分类：loan_apply 33,478 / cds_pull 38,363 / credit_run 109,636
SELECT event_type,
       COUNT(*)                  AS cnt,
       COUNT(DISTINCT flow_id)   AS flow_cnt,
       COUNT(DISTINCT user_id)   AS user_cnt,
       SUM(is_success)           AS success_cnt
FROM model.tmp_eliam_wagego_application
GROUP BY event_type
ORDER BY event_type;

-- 3. 借款申请键：loan_no 与 application_id 应各自唯一，且 application_id 不为空
SELECT COUNT(*)                                              AS loan_cnt,
       COUNT(DISTINCT loan_no)                               AS loan_no_cnt,
       COUNT(DISTINCT application_id)                        AS application_cnt,
       SUM(CASE WHEN application_id IS NULL THEN 1 ELSE 0 END) AS null_application_cnt
FROM model.tmp_eliam_wagego_application
WHERE event_type = 'loan_apply';

-- 4. 状态分布应与原表一致
SELECT status, status_desc, COUNT(*) AS cnt
FROM model.tmp_eliam_wagego_application
GROUP BY status, status_desc
ORDER BY status;
```
